## A.2 sandbox 结论（Q-09 / VR-01-02 / D-02）

| 字段 | 内容 |
|---|---|
| 取值 | `false` |
| 三步实验结果 | ① `sandbox:true` + 最小 preload 执行 `contextBridge.exposeInMainWorld('probe',{value:1})` → 通道可通，`window.probe.value === 1`；② 同一 preload 内 `require('crypto')` → `module not found: crypto`，`require('ali-oss')` → `module not found: ali-oss`，`require('fs')` → `module not found: fs`；③ 渲染世界 `window.process` 为 `undefined`，`require('fs')` 抛 `Cannot find module`（`window.require` 为 `dist/lib.js` 中 clipboard browserify 垫片，不具 Node 加载能力） |
| 结论 | `sandbox=false`。三项 require 全部失败，且 `safeStorage`/OSS SDK/进度文件 I/O 均依赖 CommonJS 第三方依赖，sandbox 下无法承载现有业务能力 |
| 能力约束 | CommonJS 第三方依赖（`node/ossstore`、`ali-oss`、`nodemailer`、`crypto`）不可在 sandbox 渲染进程加载，故业务能力必须留在 preload（非网页世界）；渲染世界安全目标改由 `contextIsolation:true` + contextBridge 白名单达成（无 Node、无原始 IPC、无任意路径） |
| 批准人 | 技术负责人（2026-11-24 批准偏离 O-04：preload 承载业务能力） |
| 日期 | 2026-11-24 |
